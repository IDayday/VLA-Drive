# Field2Plan Phase 3 Development Report

Date: 2026-08-09 UTC

## Completed implementation scope

- Added a lazy, local-only `DynamicsTeacherAdapter` and an adapter for the
  pinned official V-JEPA 2.1 ViT-L/16 384 encoder. The adapter always builds
  with `pretrained=False`, loads `ema_encoder` from the configured checkpoint,
  and never invokes an upstream download path.
- Added offline, resumable, 16-way dynamics-cache generation with content
  hashes, per-rank compiler caches, atomic entries, shard consolidation, and a
  strict runtime manifest/reader.
- Added explicit history/current/future pose transforms, future camera
  calibration, ego-motion compensation, frame-time alignment, and missing-data
  masks. A standalone visualization validates transform inverses and teacher
  frame/time correspondence.
- Added an action-free future dynamics writer. It uses current visual BEV
  features, lightweight spatial context, ordered frames 0--3 historical ego
  motion, and learned horizon embeddings. Its forward signature contains no
  draft, trajectory, future action, or GT action input.
- Added confidence-masked future latent cosine/SmoothL1 supervision, temporal
  contrast, uncertainty loss, and real-vs-time-shuffled probe logging.
- Extended trajectory-tube readout to select/interpolate the corresponding
  dynamics slice per waypoint, with independent geometry/dynamics/semantic
  gates, access masks, and source dropout.
- Added real, batch-shuffled, temporal-shuffled, supervision-no-access,
  access-no-supervision, dynamics-only, and geometry+dynamics launchers.
- Added a separate incremental 16-PPU Phase 3 checkpoint evaluator while
  retaining the Phase 2 evaluator's default experiment suite.
- Kept every Phase 3 path opt-in. Pre-Phase-3 configs leave dynamics disabled;
  `field2plan.enabled=false` still dispatches directly to legacy `QwenOFT`.
- A frozen proposal remains in eval mode even when the trainable Field2Plan
  wrapper is placed in train mode, preventing stochastic train-mode behavior
  in the current-image visual features.

PyTorch 2.4 on the local PPU requires Q/K/V to share a dtype. The official
RoPE utility promotes BF16 Q/K to FP32 through its position tensor, so the
adapter installs a process-local wrapper that casts positions and RoPE output
back to Q/K dtype. No vendored V-JEPA source or checkpoint is edited; the
compatibility behavior is recorded in the cache manifest.

## Tensor and information-flow contract

- Teacher input RGB: `[V,12,H,W,3]`, `V=3`, frames 0--11.
- Official V-JEPA input: `[V,3,12,384,384]`.
- Raw V-JEPA tokens: `[V,6,24,24,1024]`; temporal centers are
  `[0.5,2.5,4.5,6.5,8.5,10.5]` frames.
- Cached detached teacher: `[8,3,96,16,16]` float16 for future frames 4--11,
  plus confidence/valid `[8,3,16,16]`.
- Historical writer transform: `[B,4,4,4]`, frames 0--3 only.
- Main student dynamics field: `[B,8,192,64,64]` and log variance
  `[B,8,1,64,64]`.
- Teacher-space prediction/target: `[B,8,96,64,64]`; targets are projected
  from each future camera back into the current planning ego frame and detached.
- Draft physical trajectory: `[B,M,8,3]`.
- Geometry/dynamics tube context: `[B,M,8,256]`; source gates are
  `[B,M,8,S]`.
- Final normalized action: `[B,M,8,4]`.

Demonstrated future images/poses are available only to the offline cache and
detached supervision alignment. They never enter the dynamics writer or
reader at inference. The same future is not claimed to be a counterfactual
outcome for any candidate.

## Actual development validation

- Official V-JEPA checkpoint load and one-card real NAVSIM cache generation
  succeeded.
- A two-card/two-token cache was generated by independent ranks, consolidated,
  and validated through `DynamicsCacheReader`.
- A two-PPU Accelerate/DeepSpeed ZeRO-2 BF16 optimizer step completed with the
  frozen draft, DA3 geometry cache, and real V-JEPA cache. Effective batch was
  preserved at 32. The pre-spatial-writer run had finite
  `plan_loss=0.0096841`, `dynamics_cosine_loss=0.838671`,
  `dynamics_probe_margin=0.028735`, and `dynamics_valid_ratio=0.420898`;
  `delta_norm=0` confirmed initial draft parity.
- The final writer preserves history order with an ordered SE(2)-motion MLP and
  uses a `3x3` average-pool plus linear fusion for spatial context. A proposed
  depthwise-convolution implementation was rejected after its measured model
  time regressed to `7.576 s/step`. The accepted implementation completed the
  same two-PPU optimizer-step smoke with finite `plan_loss=0.0096841`,
  `dynamics_cosine_loss=0.999938`, `dynamics_smooth_l1_loss=0.023856`,
  `dynamics_probe_margin=-0.011897`, and
  `dynamics_valid_ratio=0.420898`. It measured `1.734 s` model time and
  `2.206 s` wall time; `delta_norm=0` again confirmed initial draft parity.
  The negative untrained probe margin is expected to remain an acceptance
  failure until aligned supervision learns more than shuffled supervision.
- `pytest tests/field2plan -q` completed with `124 passed`. Compileall, shell
  syntax, diff-whitespace, and new-path `.cuda()`/bare-`except` scans also
  completed successfully.

No full dynamics cache, Phase 3 training, navtest/navhard score, or SOTA result
is claimed here.

## Open scientific risks

- A positive one-batch temporal probe margin is only a plumbing sanity check;
  it is not evidence that learned future fields beat shuffled/random controls.
- V-JEPA is appearance/dynamics self-supervision, not a metric occupancy
  teacher. Geometry and dynamics must remain factorized and be evaluated both
  separately and jointly.
- The writer uses current visual features and historical ego motion rather than
  re-encoding historical camera frames online. This preserves training cost and
  the no-online-teacher rule but may limit long-horizon motion modeling.
- NAVSIM navhard processed metadata/datalist is not currently present in the
  repository checkout. Stage-1/Stage-2 evaluation must be wired and validated
  against the local navhard assets before scientific acceptance.
- A target such as PDMS greater than 92 cannot be inferred from unit losses or
  smoke tests. RL remains deferred until Phase 4 defines interpretable outcome
  labels and Phase 6 supplies reliable closed-loop evaluation.
