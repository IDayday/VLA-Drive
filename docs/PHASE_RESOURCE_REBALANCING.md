# 阶段报告与增量资源调整规则

依据：用户 2026-10-31 要求。适用于 IL、RL、评测及候选构建的阶段更新；与任务健康检查一起执行。历史主机列表不代表当前授权或空闲。

每次阶段更新必须核查当前授权、真实进程与 GPU UUID、显存、CPU/RAM、租约、待执行队列和最近完成任务。报告记录资源释放去了哪里、可以回填什么、实际调整及未调整原因。常规半小时、重要阶段事件即时更新；不因此高频轮询训练日志。

按以下顺序调整：

1. **回填现有队列**：空闲资源优先执行已登记的评测、候选构建或训练；复用既有唯一 controller，不另起重复任务。
2. **自然边界换落点**：优先在当前任务完成、下一训练阶段或恢复点本来就要启动时选择更合适的节点，不打断健康在训任务。
3. **单任务迁移**：仅当有实测吞吐、剩余工作和保存/加载/传输成本依据，且预计节省时间至少覆盖迁移成本三倍时，才从合法 native 恢复边界迁移。保留 optimizer、RNG、数据游标、pending rollout/inner 进度及 run 身份；先确认原 worker 退出，再启动接替任务。

禁止把所有任务暂停后统一重排。一次常规审阅最多迁移一个在训任务，同一任务一小时内不反复搬迁；故障恢复及授权撤销例外，仍需记录依据。显存空余、瞬时利用率为零或旧任务结束，均不足以判定资源可用。未知占用、不可见进程、未释放租约不得抢占。

不为填满 GPU 创建额外算法矩阵、恢复已终止/筛除任务、扩大预算或改变模型/数据/评分/seed。共享部署须检查显存与 CPU/评分瓶颈，保留余量；统计共享 worker 时间与端到端 wall，不能冒充独占 GPU 时间。

自动化边界：报告进行只读双快照核查、发布机器可读审阅记录；确有空闲卡及待评测 checkpoint 时可唤醒已有评测 CPU owner，仍由其现有授权/租约/并发检查决定启动。自动审阅不会暂停或迁移 native learner，也不提高既有并发上限。单任务迁移由主 agent 按上述证据执行并留下收据。没有值得调整的资源时明确记录维持现状，不为“做过调整”制造搬迁。

实现入口：`python -m tools.il_report.resource_review --probe-only`；正常 IL 报告 `python -m tools.il_report.render --once` 同步执行审阅。RL 阶段/报告事件也触发中央审阅；结果写入 IL 的 `resource_reviews_20261031/LATEST.json` 和 RL 的 `resources/RESOURCE_REVIEW_LATEST.json`。授权变化后的实际 dispatch 仍须重新核查，审阅快照不是长期资源预留。
