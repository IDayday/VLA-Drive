# P0 forward coordinator

Default is a CPU-only plan. V1 registers four origins (G1/G3 initial/mid), each
with three independent repetitions: 12 slots. Each probe itself runs A/AA/B.
The coordinator calls the frozen external producer6d16abf with the original
44c78e source binding and be5 model source, without modifying any operator,
scientific threshold or original819 native binding.

```bash
CUDA_VISIBLE_DEVICES='' /usr/bin/python3 -B tools/structured_world/run_p0_forward_probes.py \
  --manifest /mnt/project/structured-world-fgtr-round1-artifacts/20261008/perf_p0_forward_coordinator_20261011/MANIFEST_v1.json \
  --output /absolute/new/forward_plan
```

Parent freezes this small coordinator, refreshes qualification/budget/physical
resources after the24 benchmark jobs, and adds `--execute` only on the actual
zt4 host. The planned four local origins are initial_G1_common and
initial_G3_common step2, and REM/origins/G1 tag25000 / G3 tag50000. The unchanged
producer's CPU preflight verifies actual origin/source binding before GPU
execution. Planning does not claim those local files or future GPU availability
were checked. Full8 is the original forward validator's native rank contract,
not a general inference scheduling assumption.

Every attempt has a distinct observed/process directory. Private0600 PROBE.json
records exact command, coordinator and source binding before actual B. PLAN and
small receipts are private too; no copied environment is written. The producer
rechecks its source binding before B. Actual captured B timestamps must follow
both source freeze and prototype creation. Existing outputs are never reused or
overwritten. There is no SSH dispatcher, process signaling, automatic retry or
budget policy in this helper; parent owns fresh admission and routing.

The helper reuses benchmark_engineering_execution.run_job/readiness/acquire.
It holds the same hash-of-physical-pool lock used by the native benchmark, and
that lock is inherited by the owned child. Any compute app prevents launch.
The original process helper retains actual PID, exit code and whole-process
wall seconds. Exit1 is expected when the legacy strict gradient check is false;
only the process helper's exact known nonzero-exit assertion is intercepted.

To classify `completed_no_retry`, require actual P0 report + unchanged strict
COMPLETE, all8 ranks/global32 scenes, original source/preset/binding/origin,
three role-pair module inventories, q0/H_A/B0/Bt/q_final/total and all captured
weighted/raw losses finite and bitwise exact, query/count/RNG/BN/buffer/inventory
exact flags, physical trajectory exact, and an exit consistent with the actual
strict result. Original exit1 and strictFalse are retained and charged as
whole-process wall*8/3600 GPU-hours. If the legacy check actually passes, exit0
and its true original result are retained verbatim; coordinator acceptance still
remains false. Scientific errors/incomplete reports stop the matrix and preserve
attempt artifacts and costs. Missing reports are never called completed.

OBSERVATION.json is an exact-forward observation, not a V1 full gradient budget
or trainer authorization. AA_B full parameter gradient statistics remain absent;
representative activation gradients cannot supply them. `passed` and
`formal_authorized` remain false. Every repetition's strict/COMPLETE.json and
P0_FORWARD_COMPARISON.json stay distinct and unchanged.
