## 正优势中的违规样本有多少，是否真的排错

“通过mask的正优势”指`advantage>0`且该组`adv_mask=1`。它只是具有PG
资格；不表示四次inner中每一次PPO clipping之后都有同样的实际梯度。

| 完整日志与所选保存链的共同计数 | R_CANONICAL | R_CANONICAL_X1 |
|---|---:|---:|
| 安全正优势候选 | 177,055 | 175,024 |
| 违规正优势候选 | 460 | 367 |
| 违规占全部正优势候选比例 | 0.2591% | 0.2092% |
| 只因group mask而实际不参与PG的违规正号候选 | 0 | 0 |
| 违规正优势且同组有安全候选 | 340 | 270 |
| 其中高于/等于/低于最好安全候选 | 0 / 0 / 340 | 0 / 0 / 270 |
| 违规正优势且同组没有安全候选 | 120 | 97 |
| 违规类型为TTC单独失败 | 446 | 361 |
| 违规类型为NC+TTC失败 | 14 | 6 |
| 涉及不同TRAIN场景数 | 163 | 134 |
| 数量最多的前10个场景贡献 | 77 / 460 | 74 / 367 |

没有发现DAC失败的正优势候选。这与合法非负reward中DAC=0会使PDMS=0
的公式一致，但不据此推断DAC的训练或部署问题已经解决。

有安全替代的违规正优势候选，其相对最好安全候选的score差中位数均为
−0.416667原始score；最大值仍分别为−0.313250/−0.314896。它们并没有
因为某个微小数值误差排到安全候选之前。全部所选违规正优势的clip5前后
总量相同；没有被该上限截断。

原规则是组内中心化再除以公共正std。一个组如果还有更低分候选，某条
违规轨迹可能比组均值高，同时仍明显低于组中的安全轨迹。因此，仅统计
“存在安全候选却给违规候选正优势”，不能作为优势计算错误的证据。
将这些样本直接删除还会改变已登记的数据和更新语义。

一个有条件的公式检查也有助于理解：在NC=DAC=Comfort=1时，TTC=1的
canonical分数至少为7/12，TTC=0的分数最多为7/12。这不是所有候选的
通用不等式，因为Comfort和其他gate也能变化。本次两组各有2条违规
正优势候选所在组的安全候选并非全部Comfort=1；它们同样通过了实际
score排序核对。结论来自保存的真实分数，不靠把这些例外删掉来成立。

数量少不等于梯度作用小。每条候选的Jacobian、优势大小、clipping和三个
随机步骤都会影响更新。本次只有选中组的优势总量，没有全体组的优势
质量分母；不把选中组内比例当作全训练梯度占比，也不据此排除该机制
对少数重要场景的影响。

## 对下一步的约束

本次证据不支持优先通过增大噪声来消除等分组：等分已很少，而且已完成
的末次创新诊断表明噪声会损坏一部分轨迹。也不支持把违规正优势计数
直接当作概率或reward排序bug。

先完成已经运行的LAST_ODE固定计划。它只改变随机窗口，不叠加X1，
不因本报告中途调整LR、anchor、reward或清单。若它提升候选质量却不能
充分改善部署，下一项候选应是**固定TRAIN安全难例的曝光分配**：利用
已有合法SFT分层，保持真实当前策略采样和原组内完整候选，单独比较
安全难例覆盖与普通场景保持。具体配额、起点和预算尚未登记，本轮没有
启动该训练，也没有用Navtest失败场景构造清单。

这一建议的支持证据是：固定人口中NC/TTC失败曝光少、实际失败组仍可
产生安全候选、当前大部分更新为progress-only。未排除的因素包括
LoRA共享参数泛化、训练/部署时间网格差异、归一化保持和源概率代理；
因此不能仅凭曝光计数宣布课程必然有效或可以达到92。
