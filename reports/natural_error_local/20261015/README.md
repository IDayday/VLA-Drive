## 哪些 UNKNOWN 仍有可学事实

已在固定 4096 训练场景和完整 1696 开发场景上完成逐时刻及前缀审计。
LocalEvidence 与 strict repair target 使用不同 schema：

- 可靠道路违反和已知对象重叠不会随另一对象或更晚时刻未知而消失。
- 到已标注对象集合的距离是条件关系，不代表空间确定空闲。
- “没有冲突”的负标签仍要求相应车身区域具有足够支持；缺框不填零。
- track 缺失、未知可达区域、道路高度、越界、边界模糊与 observed-free 缺口分别保存。
- 事件是同一 query 位置上、当前与指定未来时刻的端点进入/释放，不是累计首次事件。
- 没有完整目标时整轨迹 MIN loss 为零；未知目标存 NaN 并由独立 mask 隔离，不填 KEEP。

开发集在 0.5 秒的道路/已标注对象距离支持分别为 1695/1660 个场景；
4 秒分别为 1691/1662。相比之下，能给出全局重叠“是/否”标签的场景仅为
26/42（0.5/4 秒）。连续条件距离覆盖高不代表完整自由空间判断覆盖高。
原生开发计划中，24 个场景有可靠道路违反，14 个有已知重叠，26 个具有局部违反
却没有完整目标；这些类别可交叠。

当前原生诊断池独立动态事件仍很少，不能以密集时间点、对象记录或重复采样 seed
虚增样本量。实际 scene/log/actor/time-window 统计保存在 `LOCAL_*_COVERAGE.json`。
该证据支持修正监督资格，尚未证明新辅助知识提高了规划。

## checker 与官方执行为何不同

完整开发集原生 q0 有 42 个 canonical 零分。4 个却被旧 strict teacher 判为 KEEP。
对这 4 个固定案例原样重跑官方模拟和评分，分数完全一致，输入计划也逐值一致：

- 两个 NC/TTC 零分案例：输入计划没有已知重叠，模拟执行后最大位置偏离约
  0.94/1.30 米；对**同一 checker**输入执行后的状态，会检出对应对象重叠。
- 两个 DAC 零分案例：执行后道路余量约为 −0.022/−0.046 米，落在局部标签的
  边界不确定带内。官方 DAC 仍然判失败。

这支持“计划几何与实际执行不同、边界定义不同”的解释。没有修改 scorer、旧标签或
阈值去消除差异。局部 KEEP 不是 canonical 执行通过，更不是现实安全保证。
这项检查不覆盖所有 checker/评分不一致，其他未知场景不能据此统一归因。

训练诊断集的交叉表已补齐：15 个原生 canonical 零分都没有被旧 checker 判为已知违反，
其中 11 个 UNCERTAIN、4 个 KEEP。43 个 checker 已知违反的原生 seed42 计划则均为
canonical 正常分组。这再次说明两种定义不能互相替代。
对训练集这 4 个 KEEP/零分案例全部重跑官方链路，均为 DAC 失败；模拟执行后的最小
道路余量分别约 −0.022、−0.024、−0.231、−0.023 米。第三例超出了既有边界模糊带，
其余三个落在带内。输入到执行的最大位置偏差约为 0.23–1.44 米。
完整交叉表和原样评分保存在 `LOCAL_TRAIN_CANONICAL_CROSS.json` 与 `KEEP_TRAIN_*`。
