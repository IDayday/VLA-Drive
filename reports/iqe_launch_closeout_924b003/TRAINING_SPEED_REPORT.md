# Query Base 训练速度汇总

仅汇总已经完成的测量；本次没有运行测试、性能测量或新训练。记录日期为 2026-10-11，不把历史运行快照当作当前现场状态。整理起点：`e4b327d3cdca9cbf0e6ff59aa5c2ea9c55822dea`。

**优化后的实际训练器稳态速度：p50 2.767 秒/步，平均 2.852 秒/步，p95 3.142 秒/步。受控前后对比提速 1.49 倍，单步耗时下降 33.0%。尚未达到 S 系列约 1.7 秒/步。**

所有行均为 8 × A800 80GB、有效 global batch 32。每一步指一次 optimizer update。

| 历史 S 系列参考 | 2,000 | 1.743 | 1.735 | 1.825 | steps 20001–22000，历史记录自身的计时口径 |

实际 CLI 从 step 21000 运行到 21032，模式为 `profile`。28 个稳态更新对应吞吐 **11.22 次场景曝光/秒**，计算为 `32 / 平均单步 wall`。这个计时窗口不包含模型/权重加载及末尾 checkpoint 保存，不能作为整个作业的平均耗时。控制实验每组实际运行 6 步，剔除 2 步预热和最后 1 步后只剩 3 步，因此以实际 CLI 的 28 步记录作为当前速度依据；两者都不是长时间全量测速。

实际 CLI 记录的 update 内部计时 p50 为 **2.673 秒**，暴露出来的数据/视觉预取等待 p50 为 **3.97 毫秒**。内部计时含等待、取数据和同步，不能当作纯 GPU kernel 时间；这些时间有包含和重叠关系，不能与单步 wall 再相加。旧日志 `seconds_per_update` 是启动以来的累计平均，含此前 checkpoint 停顿，不能拿它当作最近一步的速度。

1.49 倍仅来自同条件 A/B 的 `4.107981 / 2.752941`。历史正式作业和 S 系列另列作参考，不混入这个加速比。S 系列使用 BF16 模型、FP32 Adam master、ZeRO2/fused optimizer；当前 Query 路径保留 FP32 模型和冻结视觉链、DDP、语言/动作 BF16 autocast。这一执行差异仍需与动作头算法差异区分，不能归因于 Query 本身。已有优化没有降低输入分辨率、精度、global batch，或删除辅助目标。

本次仅整理速度证据并推送；未停止、迁移或重新启动原 Base。之后评估优化效果时，保持同一 batch、精度、辅助目标和统计窗口，比较训练器的单步 wall；不以孤立 Query 头的前向耗时替代整步速度。
