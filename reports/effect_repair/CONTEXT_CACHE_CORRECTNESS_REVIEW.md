## Narrow remaining boundary before reuse/generalization

The new extraction contract pins the collector and four protected original files plus `load_student` and three package versions. It does **not yet pin the complete inference closure**: common digest/validation code, actual DDPActionVideoForesight/DDPFullForesight, W query geometry/config/tokens, local QWen3/processor/model implementation and action DiT dependencies can affect the function without changing these selected pins. Root was notified. A pure-source dependency Merkle/pin or an explicit same immutable-clean source-snapshot restriction closes this without any weight scan or model replay. Source closure is currently PARTIAL, not PASS. This is not an objection to newly producing64 scenes from an explicitly immutable known snapshot; it prevents claiming arbitrary future source changes are already detected.

The exposed `--resume` flag currently does not select behavior: the collector automatically validates/reuses complete shards and manifests. It should be removed or documented as an idempotent alias; there must be no claim that it changes a recovery policy.

Thus d833's receipt/config logic passes its bounded CPU review, while unrestricted stale-source cache reuse is not approved. **The only prospective runtime acceptance is64 fixed TRAIN scenes, no optimizer/simulation, after the narrow source-contract closure/immutable-snapshot binding and Lead resource check.** This is not formal model, pipeline, G0 opportunity, EGR, IEG or science PASS. Actual cached tensors, real head export and new shared-context/trajectory roundtrip remain to be checked after production.
