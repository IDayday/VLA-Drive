# Structured world V1 implementation

This is a WCog-inspired structured supervision extension, not a WCog reproduction. It retains the compatible released Qwen3-VL-2B/Flow-Matching DiT checkpoint, its three current front cameras, native visual tokens, 64 historical GS/RGB queries and action tokens. The referenced agent-query branch was inspected, not merged; the selected loadable baseline uses the older GS/RGB/depth auxiliary organization. Original auxiliary parameters are strictly restored. All research variants explicitly disable historical auxiliary losses without changing the original prompt. A0 calls the original inference method; disabling the wrapper with default settings also delegates original training.

## Current inputs and supervision

`ModelInputs` is a whitelist of current RGB/calibration/augmentation metadata, optional ego state/history/navigation and a pinned current feature payload. No Scene, annotation, GT count, track ID or future trajectory enters a provider. The Qwen example contains image, instruction, current state and token only. `WorldTargets` are loaded after inference for diagnostics, and separately for training loss.

The Reader uses 64 scene and 64 agent queries, dimension256, two decoder layers. Its output dimension is read from Qwen. Image-conditioned baseline reads current native Qwen visual embeddings; BEV-conditioned variants read the real geometric provider. Original image embeddings and DeepStack stay in place. Continuous world embeddings and learned scene/agent types are inserted immediately before original action queries. Their placeholder token ID is the normal pad ID with attention enabled, never a native image ID. Native image grids and mRoPE are retained; subsequent text positions shift. The causal mask is unchanged. Singleton Qwen encoding avoids observed BF16 batch-padding kernel differences; assembled action batches are still vectorized.

The legacy outer Qwen forward exposes the pre-final-norm hidden state. A direct language-model helper exposes post-norm output instead. This was caught by real baseline parity; the corrected wrapper captures final norm input and removes its hook in `finally`. Heads read agent hidden states **after Qwen**, predicting seven classes plus no-object, xyz/lwh/sin-cos yaw and eight future xy positions. Positive dimensions are parameterized separately. Future xy is a displacement from the predicted centre; ego yaw channels are never agent motion labels.

Hungarian matching occurs once per current scene. Track IDs determine each future label, transformed by `inv(ego_t0_to_global) @ ego_future_to_global @ lidar_future_to_ego`; future missing tracks, absent annotations or irregular timestamps are masked. Current missing annotation differs from a true empty scene. Only current ROI and calibrated FOV receive no-object supervision. Overflow uses current range then track ID, suppressing unmatched no-object penalties. No future risk filtering occurs. Training capacity64 coverage is audited; development targets are not truncated to64.

## Real BEV and external boundary

The lightweight **unpretrained** provider uses learned image CNN features, calibrated projection of ego-frame cells at z={0,1,2}m, camera/height aggregation, and convolutional fusion. It is a geometric multi-plane BEV, not a reshaped image tensor or a downloaded BEVDet prior. Grid x=[1,50), y=[-20,20), resolution1m, shape49x40, x forward/y left/z up. Extrinsics map camera to ego; centre crop/resize updates intrinsics. Brown-Conrady distortion is restricted to positive radial scale/derivative. Observation support is geometric FOV, not occlusion, confidence or risk probability.

`provider_cli.py` supports directory extraction and a single current-observation request. `GeometricBEVProvider.forward(ModelInputs)` is the online API. `ExternalBEVFeatures` accepts the same pinned service tensor payload; missing features are an error. Cache identity includes actual weights/source, camera/time, scene token, image tensor and calibration hashes, image transform, grid, dtype and schema. Payload fields are whitelisted. BF16 caches must match BF16 compute. Source edits invalidate old caches. No final Qwen hidden cache is used while Reader/tokens train. Image augmentation is disabled. External features really enter Reader → Qwen → action queries, as verified by complete-policy online/cache/external equality.

The provider was adapted on training64 only. Its weak class-correct detection result is reported, not presented as a strong external prior. Frozen provider computation remains part of deployment latency.

## Trainability and recovery

Core pilots freeze original Qwen, vision, state projection and old auxiliary modules. They train original DiT, Reader, queries/types, projection and post-Qwen heads. Qwen LoRA is explicitly **off for every variant**; no unimplemented LoRA capacity is claimed. Image-only Reader position parameters are unused (no spatial input), heads with zero loss do not receive useful gradients; logs distinguish these from optimizer membership. The provider is fixed in D/E after adaptation. The adapter is a separate gated cross-attention; zero gate has a first-step gradient, attention receives gradients after the gate opens.

Frozen Qwen is not wrapped in `no_grad`: trainable input tokens backpropagate through it. Only fixed image feature extraction uses `no_grad`. The optional visual switch enables live feature extraction, optimizer inclusion and a measured parameter update. No modules are created/moved in forward. Repeated FM sampling repeats conditions and actions in the same batch order (real two-scene test, repeats8).

Loss numerators and valid counts accumulate separately. DDP compensates its averaged gradients by world_size/global_valid_count. All ranks execute identical collectives, including empty ranks. Retained-graph microbatch accumulation is available in the loss API and verified against a full batch; the pilot CLI intentionally uses batch1/no accumulation. Full-Qwen DDP validation uses `find_unused_parameters=True` because the image-only position branch is unused.

Checkpoints save every new parameter/buffer, trainable original parameters, config, optimizer, scheduler, random states and sampler order/position. Frozen originals restore from the pinned base. Key manifests/shapes/config/data identity are checked; critical omissions cannot be silently ignored with `strict=False`. The processor/base config accompany each run (older runs were packaged retrospectively and labeled). **Exact continuation is supported at optimizer boundaries with unchanged topology and deterministic math attention.** Fast attention pilots preserve checkpoint predictions but are not claimed bitwise continuation-equivalent. Actual single-process restart and two-process GPU deterministic continuation tests pass.

No trajectory VAE, multi-agent diffusion, new scorer, RL, routing, future RGB objective or counterfactual intervention model was added.

Disabling world after joint action training does not restore the original strategy: restore the original base/action checkpoint to recover original predictions.
