# 完整梯度首个实际窗口与分类器修正

实际 G1 初期窗口完成了八卡 A、A/A、A/B、A/A 对 B 的前向和完整梯度采集，包含 1146 个训练参数。GPU 成本 1.3821030122044444 GPU-hours；没有执行 optimizer 更新。原 strict=False、exit=1 和原分类失败保留。

分类器最初失败的原因是 JSON 的 sort_keys 将参数字典按名称排序，而原生产器按 optimizer inventory 的顺序遍历。最大误差列表中零误差并列项的展示顺序因而不同。将只读重算输入恢复到已登记 inventory 顺序后，全部数值字段与原汇总精确相等；133 处差异均为并列参数名称顺序，数值差异为零。原始报告没有改写，也没有改变比较阈值。

CPU 回归测试 30 项通过，覆盖冻结生产器真实写出接口、完整三对梯度、原始实际报告、缺失/篡改拒绝、首窗口显式复用和成本计入。测试中的小 CPU fixture 不是研究证据。父进程使用专用测试入口及真实保存报告执行；普通 unittest discovery 不提供该入口要求的 actual-report 参数。

这不是数值验收通过。按原冻结标准，仍存在真实未通过项：`gradient/by_optimizer_group/1/AA_B/norm_relative: fresh AA envelope`。A/A 范数相对差为 2.7435946269e-5，A/A 对 B 为 4.69876989945e-5。此失败记录与全部原严格结果保留；正式任务继续使用已接受的原执行模式。

新协调器支持显式复用这一完整窗口，剩余只运行 11 个新窗口。原窗口 GPU-hours 计入同一 30 GPU-hour 内部有限测试阶段，不重复计算或重新生成权重。新窗口需要先冻结新协调器及实际资源路由，再启动；本记录不授予正式训练的工程加速模式验收。
