# Fixed original-S0 development contexts

This separate interface admits the actual pre-existing1696-scene/16-log DEV population for the final comparison. It does not retune an intervention, target, loss, replay proportion, threshold or checkpoint from DEV outcomes. Navtest is not opened.

`collect_evaluation_context --phase register` takes explicit current-root, metric-index, historical-export, historical-score-identity and a new bounded campaign output. It checks the complete current-only DEV index, exact historical S0 checkpoint/FP32/TF32-off/Euler10/seed42 identity and original metric-index bytes. It verifies the full train/dev source-log intersection is empty. It fixes every current record, three-view image, metric-cache and original prediction/receipt hash before new DEV generation. Hashing is paced in1MiB blocks (default128MiB/s), with concurrent file-change detection. It reads no GT files or score CSV values. Metric payloads are hashed but not deserialized by the encoder. The old physical prediction is a fixed replay witness, not a target for learning.

The registry pins the same immutable Base/extraction runtime and current official protocol as TRAIN, but is typed `action_effect_evaluation_registration_v1`, `split=dev`, `role=dev_report`, `for_training=false`. Its flat `population` contains scene/log/current/image/metric/reference pins. Those offline references are not feature-record/model inputs. `spec`, Base hash, numeric-runtime hash and metric pins allow the common official scorer to evaluate final predictions without reading GT into inference.

`--phase collect --rank R --world-size W --device cuda:N --max-seconds T` allocates fixed16-scene immutable shards to workers by shard-index modulo W, at most8 workers. Different ranks do not share a global collection lock. Each shard uses an exclusive claim, checksum and atomic completion. A paused or failed shard remains incomplete; later workers can resume completed identity-matching shards with another explicit worker count. No sampler or scene order changes. The existing S0 action-head receipt is referenced; no duplicate3GB head is saved. Mature FP32 master S0 is strictly loaded, eval/TF32-off/deterministic, same scene noise and originalEuler10. Exactly one visual and language forward is hook-counted per scene.

Each record stores W144/A8 FP32, original action-only planning condition8x2048, legal normalized relative-history ego1x4, raw/physical trajectory and fixed noise. No ego target, score, feedback, future actor, GT or metric path is stored in feature records. The planner condition equals the original final action states. Every generated physical trajectory must match the registered original FP32 prediction bitwise; mismatches fail without widening tolerance. First registration/collection must pass independent review before GPU dispatch.

`--phase finalize` requires every expected complete shard, full payload checksum, finite/detached FP32 schema, exact ordered coverage, original scene noise and each historical physical witness. Only then is `EVAL_CONTEXT_MANIFEST.json` COMPLETE. `--phase verify` performs the same full revalidation. A stale COMPLETE marker cannot promote missing/corrupt data. There is no flag to skip full record verification during finalization. Approximate uncompressed new tensor payload is2.07GiB from audited shapes; actual stored bytes are only reported after finalization. This is compact frozen-VLA context, not a multi-TB frozen visual cache.

`evaluation_context_data.EvaluationContextReader(manifest,binding_path=None,max_shards=2)` is an independent DEV-only reader. `binding` is the evaluation registry, `population`/`rows` map scene IDs, and `__getitem__` returns only the strict typed feature record. It verifies complete manifest/shard coverage and maintains a bounded mmap-free torch-shard LRU with version-stamp invalidation. The shared `batch_context` forwards only memory/ego/mask. Existing TRAIN `ContextReader`, G1 dataset and repair-data gates remain unchanged and reject this DEV schema. Final scoring performs separate CPU simulator calls; no feature extraction is a PDMS result.
