# 同一专家端点：训练场景与对应测试场景收益

结论：三个专家在实际训练集上均学到了明显改善；对应 Base 失败测试组中，道路/交互有正向平均收益，进度组平均退化。不能把训练拟合或全池 Oracle 提升等同于所有分组均已泛化。

分数均为 PDMS×100，差值为百分点。Base 为同一 70k 权重；专家固定为 road E11 EMA3000、interaction raw3000、safe_progress raw1000，均由原 stage_val 规则选定。未根据测试结果更换端点。

这些是完整测试清单中按 Base 分项筛出的对应失败组，不使用专家胜负、Scorer 或 GT 筛选。道路与交互重叠 58 场景，另报告 exclusive/intersection 结果；不能把重叠行简单相加。

**重要限制：测试组没有训练集的优化目标审计筛选，因此是更宽的 F_test，不是声称与 H_train 完全同分布的严格 H_test。** 严格目标筛选留出的 H_val 只有道路1/1log、交互9/8logs、进度11/8logs；对应直接收益 +1.17、+13.74、+8.46 分，支持规模不足以单独作稳健泛化结论，且 stage_val 用于选端点。

这是已见全局测试结果后的解释性分析。分组规则沿用训练前记录，本轮在读取分组专家结果前封存协议，不把它包装成未接触测试的预注册验证。区间按 log 整组配对重采样2000次、seed11235；原始结果另给三项主要分组结论的 Bonferroni 区间，方向未改变。单训练 seed 不代表多 seed 稳定性。

## 收益与代价必须一起看

|对应组|提升>1分|下降>1分|其余|正收益均值|负损失均值|≥80分→0分|新增NC/DAC/TTC失败|
|---|---:|---:|---:|---:|---:|---:|---|
|道路组|212|24|386|24.35|1.75|6|12/3/27|
|交互组|203|52|348|16.57|2.94|0|19/20/2|
|进度组|1893|301|85|5.20|8.68|186|19/172/128|

正收益/负损失都除以该组全部场景数，净变化严格等于前者减后者；不是在成功子集上求均值。进度专家 1893/2279=83.06% 场景提升超过1分，但 +5.20 分平均正收益被 8.68 分平均损失抵消，其中186个 Base 高分场景变零分。这是“胜率高却净收益负”的真实例子，不能只靠胜率宣布成功。

道路组 DAC 失败346→187，同时新增 NC失败12、DAC失败3、TTC失败27；交互组 NC失败231→206、TTC失败597→427，同时新增 NC失败19、DAC失败20、TTC失败2。有群体平均改善并不等于每场景安全。进度组新增 NC19、DAC172、TTC128。
