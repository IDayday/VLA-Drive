# ReCogDrive IL 与 RL：完整 Navtest 配对结果（2026-10-18）

**本次结果支持：RL 提高了 PDMS，同时原始 IL loss 与对日志 GT 的轨迹拟合误差均增大。**
官方 2B IL/RL 配对权重；完整 NAVSIM v1 Navtest **12146 场景 / 136 logs**；两组均零失败。
每场景8组配对扩散噪声/时间，共97168组；实际执行各采样一条轨迹，scene-bound seed42。没有训练或检查点选择。

## 逐场景证据

- 10851 / 12146（89.34%）场景的 RL IL-loss 更高。
- 9856 / 12146（81.15%）场景的 RL ADE 更大。
- PDMS 提升 6492 个、下降 1847 个、相同 3807 个。
- PDMS 提升的 6492 个场景中，5272 个（81.21%）ADE 反而增大；5730 个 IL-loss 增大。
- IL零分→RL非零 523 个；IL非零→RL零分 152 个；两者均零 330 个。总零分从 853 减至 482，净减少 371。

## 解释与可支持的结论

这对权重证明了一个具体实例：更低的模仿损失、更贴近唯一一条日志轨迹，并不是更高 PDMS 的必要条件。RL 改变了计划分布，使官方规划评分提高，同时牺牲了上述两种 GT 拟合指标。
合理解释是两类目标不同：IL 要还原日志行为的条件去噪目标；RL 直接优化规划回报，允许偏离日志中那一条轨迹。分项与逐场景结果支持这种目标取舍，但本次没有隔离是哪一条 RL reward、哪类数据或哪一步更新造成变化，不能写成机制已被完全证明。
对当前辅助任务研究的启示是：辅助预测误差、ego GT 拟合误差与实际规划收益必须分别检验，不能只用更低 imitation loss 判断规划上限。这个结果也不能直接证明某个新辅助任务有效，或证明所有 RL 都会损害 GT 拟合。

局限：一个官方 IL→RL 谱系、一个实际轨迹采样seed、同一冻结VLM；不是多个独立训练seed。8个loss draws是Monte Carlo估计。5000次log-cluster bootstrap保留真实scene权重，不把多个draw当独立样本。本轮仅测试集事后统计，未用Navtest训练、调参或选择检查点。

## 完整性、执行与成本

权重及VLM的哈希与官方不可变revision一致；RL.old_policy的347个状态张量与独立IL逐位相同。严格加载347个执行状态，无missing-key吞咽。原五步DDIM，非S/G十步FM；VLM沿用官方BF16，planner/loss为FP32，TF32关闭。
单分片4场景smoke与完整8分片运行的轨迹及全部loss draws逐位相同；原始执行入口一致性检查见 `VALIDATION.json` / `SHARD_INVARIANCE.json`。
续算只交换GPU路由；worker源码字节与科学身份保持一致。旧续算回执中的 `parity_first_scene=true` 是旧脚本静态字段，不作为额外验证证据；最终代码已改为记录真实校验token以及复用/新算场景数，未改模型或损失。
首次汇总因TTC字段简称不匹配停止，随后使用原canonical字段 `time_to_collision_within_bound` 汇总；没有重算或修改任何官方分数。
实际推理+评分墙钟 23.74 分钟（含路由切换间隔），约 2.359 GPU-worker驻留小时；该值含模型加载、共享争用与IO，不是CUDA kernel时间或独占吞吐。单worker峰值allocated约 5.222 GiB。CPU评分每模型4进程，CPU忙时未单独测量。未生成新模型或视觉特征缓存。
本次所有GPU与CPU评分进程已退出，没有停止其它真实工作负载，也没有恢复任何暂停训练。
