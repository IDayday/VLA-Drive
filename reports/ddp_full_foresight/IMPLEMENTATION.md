# Full DDP foresight implementation

C0–C5 now mean the full four-loss method. The sealed `configs/dino_tradeoff` current-only campaign retains its original name and semantics; it is not the cost or planning baseline for this experiment. Historical 89.41 is unverified background, not a reproduced result.

`DDPFullForesight` reuses the original ego DiT (1536, 24 layers, four ego channels, eight points, FM repeat8, ten inference steps). It adds view/row/column query identities to W before action queries under the native Qwen causal attention. Current and future DINO share one two-layer 512-dimensional cross-attention head. The independent interaction head reads this same W. There is one current Qwen forward per training batch. Current weight is exactly1; only future/interaction weights warm up. New auxiliary weights must be supplied explicitly from training-only gradient calibration.

No online teacher, detector, joint vehicle generator, WAN, depth, reward, scorer or auxiliary RGB action head is instantiated. Deployment strips both readout heads and retains W. Generic Qwen and DINO identities remain pinned in the inherited source manifest; driving parameters start randomly. Local Action-Only prompt/token choices are explicit new implementation choices, not an exact reproduction of unavailable historical code.

The real GT-MAE data builder, balanced whole-actor masking, random-initialized 512×6 encoder, teacher trainer, validation, frozen selection and fresh ego-hidden export are implemented in `tools/foresight/prepare_vehicle_trajectories.py`, `train_trajectory_mae.py`, `freeze_teacher.py`, `export_interaction_targets.py`. `tools/full_foresight/verify_teacher.py` verified reuse of their completed101592-scene30-epoch run, including exact source definitions, checkpoint hash, split agreement and32 fresh masked encodings. The maximum CPU/CUDA FP32 export difference was9.54e-6 against a predeclared3e-5 absolute/2e-5 relative tolerance. This does not reuse an old JointSceneFlow or driving policy. See `TEACHER_REUSE.json` for costs and real development metrics, including poor static-vehicle performance relative to the stationary reference.

`build_index.py` preserves verified h0/1/2/4 timestamps, source RGB keys and log-disjoint populations while changing storage offsets. `cache_dino_targets.py` encodes four actual resolutions, independently pools each image, and writes separate six-candidate identities. Compatible existing per-image current targets are reused only after recipe and SHA checks; cache schemas are not renamed. The complete six-target population is608730 images,792887869440 FP16 feature bytes excluding metadata. Local replicas must be staged per configuration rather than all six on every disk.
