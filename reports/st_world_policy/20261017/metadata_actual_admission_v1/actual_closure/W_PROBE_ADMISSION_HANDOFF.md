The next distinct blocker remains **BLOCKED_TYPED_W_ADMISSION**. `tools/st_world_policy/metadata_storage.py::validate_package` (lines 132–157 in reviewed source) calls `_registration` for every claim outside the immutable metadata baseline. That accepts only `st_metadata_build_registration_v1`; an honestly typed learned-W tensor claim is consequently rejected. Do not relabel tensors as metadata or edit the historical baseline to evade this check.

## Smallest recommended change

1. Add one explicit, narrowly typed frozen-W package to a **new immutable policy**, using an additive migration from the actual v6 ledger and the same `CLAIMS.lock`. Preserve the v4/v6 policy files, migration snapshots/history, every existing claim/reservation, the original metadata baseline and its 4 GiB maximum. Verify quiescence of old mutating writers before the core transition; unchanged read-only training runtimes do not switch policy. Keep the original 768 GiB aggregate cap and the checkpoint/free-floor checks.
2. Register at most the eight exact learned-W train/dev roots under the already allowed cache namespace. Bind their existing extraction signature, native checkpoint and runtime identity, role/population, FP32 W/mask schema, and exact output/staging/metadata bounds. A thin claim/registration adapter may be needed because `spatial_probe.extract` currently creates an ordinary tensor claim. Do not add a second trainer or generic package framework.
3. Make package membership explicit and disjoint. Known metadata claims continue to pass the existing metadata registration checks and consume the original metadata package; known frozen-W claims pass their own typed checks and consume the separate ≤1 GiB W package. Unknown kinds, unregistered roots, overlapping roots, dual membership and budget inflation fail closed. A new kind must not become a blanket bypass around `_registration`. Old baseline claims are preserved verbatim, not reclassified.
4. Add all declared bytes exactly once to the same campaign total. W output, staging, record/control metadata and failed partial files stay charged. The metadata4GiB allowance does not grow, W does not receive a second768GiB allowance, and a small final file size does not automatically release its precharge. Preserve same-lock admission before writes, continuing path/size/free-floor checks, checkpoint commitments, bounded process supervision and retained failure evidence.
5. Keep probe fitting outputs separate: four ≤64 MiB checkpoint/output roots (256 MiB total), with bounded logs explicitly included in the checkpoint/output commitments. These are not W cache or metadata-package allowances. Refresh the commitment receipt when binding these outputs; do not hide them inside an unrelated reserve or automatically delete any existing checkpoint.

## Required focused negatives and compatibility checks

- Existing v6 metadata declarations and old claim records remain unchanged through the new migration. Metadata stays ≤4 GiB, W stays ≤1 GiB, and all reservations together stay ≤768 GiB. Test exact boundary and one-byte overflow independently and in the aggregate.
- Unknown/mislabelled kinds, incorrect signatures, changed source/native checkpoint/population/precision, duplicate membership, parent/child root overlap, registration conflicts and excessive staging are rejected before writes. W tensors cannot be admitted under the metadata identity.
- Migration interruption/replay retains old claims and snapshots; concurrent old/new writers cannot both mutate incompatible ledger cores. Repeat admission is idempotent for the exact identity and refuses conflicts. Reusing an old policy after migration fails closed, while unchanged old read-only consumers continue.
- Existing metadata callback and controller protections still run. Test expiry of quiescence/checkpoint evidence, low free space, missing precharge, retained failed partials, and source-capability mismatch. Do not weaken current/future metadata protections to permit W.
- Bind and test the actual extractor's emitted claim schema, rather than validating a separate fabricated claim that production never uses. Keep tensor dtype/content checks in the appropriate extraction correctness review.
