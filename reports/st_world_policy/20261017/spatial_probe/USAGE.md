# Frozen learned-W diagnostic handoff

Status: implementation for independent review, no real W extraction or fit dispatched. Source/runtime and the actual5000 native checkpoints must be bound by Lead after completion. This implementation neither supplies nor signs formal approvals.

The fixed `PROTOCOL.json` registers the original64train/16dev manifests and existing label-manifest SHA, common hidden2048 (verified in the S0 parent binding's `framework.qwenvl.vl_hidden_dim`), one fresh two-output head and the agreed300-exposure-cycle diagnostic. It intentionally differs from Evidence's draft two-independent-head/512-valid-patch proposal: here all arms receive the same scene2 × view3 ×32 uniform native patches, independent of masks; each task uses its own valid denominator, then loss weights1/1. Every task/scene retains zero-valid population in output. Numerical choices remain an unoptimized new hypothesis. This protocol is not a launch approval.

All new CLI arguments are required where shown; unknown arguments fail. Recipes cannot be overridden on the command line. Use the production environment:

```bash
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 /root/miniconda3/envs/ddp/bin/python -m tools.st_world_policy.spatial_probe --help
/root/miniconda3/envs/ddp/bin/python -m tools.st_world_policy.spatial_probe plan-cache --binding /ABS/ACTUAL_BINDING.json --output /ABS/FROZEN_W_ROOT
/root/miniconda3/envs/ddp/bin/python -m tools.st_world_policy.spatial_probe extract --binding /ABS/ACTUAL_BINDING.json --output /ABS/FROZEN_W_ROOT --storage-policy /ABS/EXISTING_CAMPAIGN_STORAGE_POLICY.json
/root/miniconda3/envs/ddp/bin/python -m tools.st_world_policy.spatial_probe fit --registration /ABS/ACTUAL_FIT_REGISTRATION.json --output /ABS/PROBE_ROOT
/root/miniconda3/envs/ddp/bin/python -m tools.st_world_policy.spatial_probe fit --registration /ABS/ACTUAL_FIT_REGISTRATION.json --output /ABS/PROBE_ROOT --resume
```

These are interface documentation, not executed experiment commands. Placeholder paths must be replaced with reviewed real identities; there are no mock checkpoint/image defaults. Git source must be clean and equal the bound source SHA. `runtime_environment()` captures the existing campaign environment plus the installed scikit-learn version. Use actual available allocated device identity and max_seconds <=7200 per invocation.

Extraction binding exact fields: schema=`st_spatial_w_binding_v1`, source_sha, environment, device, training_registration=`{path,sha256}`, checkpoint_tag, checkpoint_identity (the strict native reader's record sha256), arm=`S-P0|S-P1|S-P2|S-P3`, observations=`{current_root,manifest:{path,sha256},identity,split}`, hidden_dim, memory_tokens, max_seconds, identity. `identity=st_world_schema.identity_hash(body_without_identity)`. Manifest must contain exactly64train or16dev; endpoint exactly5000 FORMAL, current-only source; tokens144 or288 according to arm, hidden dimension must equal the actual parent binding. Observation identity comes from unchanged `STObservationDataset`; only genuine pinned images are read. No labels, ego-target files, teacher tensors or metric cache are opened by this path. Model is `load_world_checkpoint(...,strip=True)`, eval and requires_grad=False; calls only `encode_inputs`. It checks parameter/buffer versions and FP32 W and writes no probe output. All learned W slots are valid for these current-only arms; label masks never become memory masks.

`plan-cache` validates immutable native/input identities and static Python/package/build metadata, emits cache_identity/root and output/staging/metadata byte requirements, without generating W. It calls no CUDA/cuDNN API and allocates no model. Its result explicitly says `runtime_check=metadata_only` and defers cuDNN/device verification; the full expected runtime remains in the immutable signature. Actual extraction/fit retains complete environment checks and actual device activation before model execution. Lead must declare those fields under the existing StorageBudget policy before extract; the writer refuses undeclared/inadequate claims and precharges each write. It uses a flat directory with identity.json, scene safetensors/JSON receipts and COMPLETE.json. Repeat extract resumes only exact identities/checksums. Unreceipted partial files remain charged, never automatically deleted. Eight train/dev cache roots (four arms) total about450MiB raw W at H2048, plus masks, metadata and staging; no full-dataset path exists.

Fit registration exact fields: schema=`st_spatial_probe_fit_v1`, protocol=`{path,sha256}`, caches=`{train:{root,identity},dev:{root,identity}}`, arm, source_sha, environment, device, max_seconds, max_output_bytes (positive <=64MiB), identity. Training/dev caches must match the protocol scene order, label roles, same native checkpoint and common hidden width. Labels are read only here, verified against the original manifest; statistics fit only train. No action model or pretrained auxiliary head is loaded by fit. The head's initial tensor hashes/parameter count and normalized-target statistics are written to MANIFEST.json. The intended four-arm comparison must use this same pinned protocol and compare initial hashes.

Checkpoint slots probe_a.pt/probe_b.pt contain probe/optimizer/RNG/scene+patch streams/cursor and complete exposure history. STATE.json atomically publishes one durable slot; the previous slot survives an interrupted write. Small CPU/CUDA conditional RNG code follows the already inspected common train_mechanism helper formula; it is kept local to avoid importing an unrelated graph/flow trainer. Resume requires original registration/environment/input/cache/label identities. There is no best-epoch selection, no scheduler or auxiliary state to restore. No-valid cycles consume exposure but do not apply AdamW decay. The fixed300 endpoint counts exposure cycles; actual AdamW updates equal `sum(row["optimizer_step"] for row in RESULT["exposure"])` and can be fewer than300. A final300-cycle resume performs no additional optimizer update. Wall checks occur at bounded model/extraction/optimizer/evaluation boundaries; a single native model load/scene call can exceed the wall budget before returning.

RESULT.json contains per-exposure-cycle task loss, valid counts, scene IDs via the fixed manifest, patch hash and exposure, plus train/dev scene/view/log populations, small PR-AUC (average precision), ROC-AUC and balanced accuracy at logit0, and depth MAE/RMSE/AbsRel with1–10/10–30/30–80m bands. Empty or single-class populations keep null metrics and valid counts. Exponentiated predictions are not clipped to the observed depth interval. Nonfinite outputs fail the arm rather than deleting scenes. RESULT is only written at final300; budget interruptions retain the checkpoint and must be resumed to finish evaluation.

CPU tests use explicit synthetic tensors and metadata only. They do not establish actual image extraction, native checkpoint cost, real frozen-W convergence or a scientific result. Real cache/fit validation and independent correctness/efficiency review remain Lead's subsequent work.
