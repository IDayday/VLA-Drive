# Learned-W spatial readout design card (implementation pending independent review)

Design ID: ST-LEARNED-W-SPATIAL-001. Base: 6c4de2cb28bfaa3a55bcd2d6ffe3e05c2b5e737f. Question: do the four existing spatial arms preserve small-vehicle region and valid depth information readable from frozen learned W at equal readout capacity? This satisfies contract §5.4 as a bounded diagnostic; it does not replace full 1696-scene PDMS or establish generalization.

Existing evidence inspected: `checkpoints.load_world_checkpoint` strictly reconstructs canonical FP32 native masters, removes auxiliary heads with strip=True, and returns checkpoint/runtime identity; `STObservationDataset` reads only pinned train/dev current observations and genuine source images; `SpaceTimeStudent.encode_inputs` returns unreshaped W without the training forward/loss. `SparseFeatureReadout` uses view/xy/time queries over all W via the existing CrossReadout. All are at the base SHA above. Existing labels are generated by `reports/st_world_policy/history_data/spatial_probes.py::current_labels` from raw current LiDAR and vehicle boxes. They are not DINO labels or pixel segmentation ground truth.

Official components inspected: PyTorch 2.8 [BCEWithLogitsLoss](https://docs.pytorch.org/docs/2.8/generated/torch.nn.BCEWithLogitsLoss.html), unreduced positive weighting and reductions; [SmoothL1Loss](https://docs.pytorch.org/docs/2.8/generated/torch.nn.SmoothL1Loss.html), beta and sum/mean reduction. These justify component semantics, not the probe architecture or numerical choices. Evidence agent's DINOv3 frozen-backbone readout review supports the evaluation principle only; its patch linear head is not this cross-attention adaptation.

New hypothesis, confirmed by Lead in this session before implementation: initialize a fresh shared two-output SparseFeatureReadout(H,2), dim128/layer1/heads4, allowed_times_s=(0,), seed42; output0 standardized log-depth and output1 small-vehicle logit. Every arm uses identical H, parameter names/count and initialization. W48/96 changes memory length only (144/288 total tokens). Never load trained auxiliary sparse_readout parameters. Hypothesis: equal small-head exposure can expose relative spatial readability; neither convergence nor capacity sufficiency is established.

Fixed unoptimized recipe: 300 updates, AdamW lr1e-3/wd1e-3/betas(.9,.999)/eps1e-8, grad clip1; each update two uniformly drawn train scenes (with replacement), each view 32 uniform distinct positions in native18x24. Same independent scene/patch streams for all arms, sampling independent of labels. Query is view ID, patch-center xy in [-1,1], t=0. Loss is sum of two task means: SmoothL1(beta=.1) standardized log depth and train-only weighted BCE; task denominators count only that task's valid patches. A zero-valid task retains a differentiable zero; fully empty update has no optimizer/weight-decay change but consumes its registered exposure. Depth log mean/population std and class weight neg/pos use only full fixed train labels. No dev epoch/width/threshold selection, fixed logit0 classification, final300 only.

Fixed 64train/16dev manifests predate this protocol; all source and label references are hash pinned. Evidence initially independently rechecked32train/16dev; remaining32 were independently rechecked subsequently (4.72s); both batches together exactly equal the locked64train. All64train/16dev now have real source/label/calibration hash checks. Small positives require source projected small vehicle boxes plus nearest-LiDAR support; negatives exclude boxes and unknowns. Source camera exposures have no independent timestamp, so inherit source t0/calibration alignment; do not claim independent motion/time compensation. Depth is valid raw-grid LiDAR support at1–80m. No invented road-image boundary. Qwen input preprocessing remains original; query positions refer to the existing label canvas, never a geometric reshape of W.

Controls/tests: target values cannot enter extraction API; malformed scene/hash/checkpoint/runtime is refused; query positions/view/time; W48/96 equal capacity/init; all-zero mask and distinct valid populations; actual optimizer change in fresh probe with frozen W unchanged; interrupted next batch and parameters exactly reproduce CPU continuation. Unit tensor fixtures are explicitly synthetic; no fake image/model fixture is presented as a real extraction result.

Resource boundary for this implementation: GPU0, simulation0, actual W cache0, actual probe fit0; CPU2 threads, tests <=120s. Four-arm64+16 FP32 payload is Nscene*(3*144+288)*H*4 bytes (H=2048 example:450MiB), with separately reserved metadata/staging.
