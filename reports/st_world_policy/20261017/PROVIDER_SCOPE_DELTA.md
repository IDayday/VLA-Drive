## What is established and what is not

The fixed-eight raw teacher comparison passed regrouping, partial LRU, cold
rebuild, masks and RNG on the actual64-scene population. The separate legacy
comparison was also bitwise equal. The teacher is still FP32, frozen and eval;
only actual requests are returned after internal padding, and no target tensor
is written to disk. Existing real evidence is unchanged.

Read-only student snapshot during this assessment: continuous RESULT is PAUSED
at completed2, new_updates2. No split RESULT existed at this observation. A
completed continuous invocation is **not** an exact-resume comparison result.
Do not treat the raw-teacher qualification or a complete checkpoint as proof
that interrupted and uninterrupted student updates match.

change previously registered SMOKE behavior.

## Smallest next PROFILE patch, after evidence exists

The smallest possible additional interface diagnostic could reuse the already
qualified64-scene descriptor and frozen PCA scope, same registered64-scene
ordering and original epoch sampler. This is optional, not a substitute for the
requested representative PROFILE using the complete original training manifest.
It cannot estimate full-population hit rates or certify the formal101,592-scene
path. If Lead requests that full-population PROFILE, the bounded metadata work
below must happen first; do not replace its population with this64-scene fixture.

Proposed changed call sites are limited to:

1. `training_config.validate_config` passes full resolved execution (stop_after,
   sample_limit, world_size and batch) to the existing provider-option validator.
2. `teacher_provider.validate_option` retains all legacy SMOKE checks and the
   unconditional FORMAL refusal. Its new PROFILE branch must require explicit,
   immutable pins for the real native-resume comparison and independent resource
   review, bound to the provider/PCA/source/backend/population and requested
   topology. Raw teacher success alone does not satisfy it. Exact report schemas
   must follow the actual reviewers' artifacts, not a permissive generic PASS
   parser invented by this implementer.
3. A small separately named PROFILE metadata writer reuses the same descriptor,
   fixed basis and existing trainer. It checks stop_after≤256, the actual sample
   count and a positive bounded invocation wall limit. For complete timing, it
   additionally preserves the existing240-update window. It must not shorten the
   20k cosine/warm1000 schedule to the measurement length or reuse SMOKE weights.
4. No change is required to fixed8 compute, loss, sampler, target requests,
   dataset row order, source-reader tensor format, native checkpoint or PCA math
   for this same-population diagnostic. New profile source/config/lease gets a
   new run identity. The completed SMOKE runtime remains immutable.

This patch is intentionally **not applied** yet: exact student recovery and the
PROFILE resource review are still pending at this assessment. Tests added here
prove current PROFILE/FORMAL flags cannot bypass the existing provider guard.
No empty protocol, alternate trainer, provisional launch flag or fictitious
approval file has been added.

For a different world size, rank-local teacher construction and global failure
coordination need bounded qualification on that actual topology. A single-rank
1+1 comparison does not establish all-rank cache-failure behavior or memory use.
The reviewer should account for one frozen teacher and metadata instance per
rank, shared IO, CPU allocation, checkpoint capacity and native pause timing.

## Why full registered temporal training needs a second, specific step

The original full train population is101,592 scenes /1,176 logs in the prior
audited `temporal_bounded_storage_feasibility_v1/FEASIBILITY.json`. This assessment
did not deserialize the full source index or full current-cache manifests.
Only the following actual file sizes were read:

| Existing asset | Actual bytes |
|---|---:|
|64-scene full physical-future TEACHER_REQUESTS |502,318|
|64-scene pinned selected manifest |19,746|
|256-scene current source requests |494,248|
|Full native384 current-cache identity.json |145,979,873|
|Full native384 current-cache requests.json |170,157,016|
|Original student current index.json |9,549,650|

The full current source's two JSON files already exceed the provider's32MiB
per-file preparation cap. `TeacherCacheReader` currently loads both metadata
trees, reconstructs all expected unique records and materializes lookup maps.
`BoundedTeacherProvider` serializes, deep-copies and indexes its entire target
manifest. Several validation/PCA setup paths instantiate readers again. RAM
tensor limits do not bound these Python metadata objects. Raising a constant
would therefore be an unmeasured per-rank memory expansion, not a production
bounded-reading solution.

The smallest eventual data-side change is a bounded metadata index/view over the
**unchanged** original manifest and COMPLETE source: exact scene ID to original
future record references and exact payload key to original shard/row. Build only
metadata under an explicit budget; retain original manifest/source checksums and
atomic completion. Do not copy or relabel teacher tensors, create fake COMPLETE
receipts, or introduce a new server/cache service. The existing dataset sampler
must still index every original row in its original registered order. A bounded
metadata view may change how a row is found, never which row is consumed.

This requires a narrow extension of the existing reader/provider interface and
tests for missing/corrupt entries, cross-shard coverage, role/byte identity and
cold-resume order. It cannot be delivered truthfully by accepting a different
full source path in the64-scene descriptor. It also needs the complete original
future timestamp/image-SHA manifest, including physically missing-frame masks;
current-only metadata cannot be renamed into four-future supervision.

The raw/PCA identity is not an obstacle requiring refit. Actual metadata confirms
`pca_fixed384_full_current_v2/PCA.json` and the existing smoke basis share PCA
identity `268723c8da3151492fd20a81b0f6f541f348a1187222132b055f4e4a528bfd46`
and tensor SHA256 `0b03fc98e2c7c4377dcfe669cad885c09e95536c659cf543dee3c95e2256acc1`.
The basis stays frozen. A future full provider needs an explicit new application
scope referencing these same original statistics, not a second PCA fit.

Once population reading is bounded and the existing formal spatial/temporal
decisions are made by Lead, a separate registered temporal run can use all
original train rows, existing three independent formal reviews and source/resource
pins. This assessment chooses neither its cell nor its W/spatial winner, and
does not open the formal provider gate.

## RAM, timing and non-goals

For the native384 raw teacher, a record is1,769,904 bytes. The qualified LRU is
14,159,232 bytes/rank; a complete15-record scene is26,548,560 bytes before caller
batch stacking, PCA outputs, pixels, model weights and activations. These are
separate allocations and bounds, not an additive measured peak. The provider's
`memory_report` already states those exclusions. A new resource review must use
actual training peaks and native checkpoint costs, rather than teacher-only
peak GPU memory or the nominal LRU size.

Initial PROFILE remains synchronous with loader0. Its misses expose real teacher
work in the training critical path. There is no promise that it is as fast as a
complete future tensor cache. Measure actual requests, padded compute slots, IO,
teacher calls, data wait and normal/update+checkpoint timings separately. Do not
claim a full-scale hit rate from repeatedly cycling64 scenes.

No BF16 teacher, lower resolution, fewer future labels, different sampled pair,
second teacher service, TB disk cache, changed GT, autonomous eviction of old
artifacts or changed formal recipe is part of the proposed delta.
