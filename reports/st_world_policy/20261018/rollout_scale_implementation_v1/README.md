# Complete-rollout advantage scaling implementation

The new module implements only `scene_center_rollout_std_v1`. It preserves the actual legacy FP32 sum/count scene centering, computes two-pass FP64 central moments over all complete G4 candidates across the process group, uses sample correction 1 and fixed epsilon `1e-10` after the square root, and returns detached FP32 advantages. The numerator is never globally re-centered. Zero scenes remain zero, while the original BC computation remains the caller’s responsibility.

`normalize_rollout_advantages(rewards, valid, *, collective_device, expected_global_count, common_identity, local_identity, distributed=True)` returns the same `[scene,4]` shape and a JSON receipt. `normalization_contract()` supplies a fresh execution identity. `receipt_sha256()` hashes canonical JSON. Tensor hashes reuse the existing `policy_snapshot.tensor_hash`, including dtype and shape; a flattened caller must restore `[scene,4]` before checking the receipt.

Input shape, dtype, detachedness, range, full validity, old-policy identity, expected population and JSON identity preparation occur inside a caught local phase. All ranks vote on failure before the fixed-size identity gather and any statistics reduction. Subsequent moment and output preparation have matching failure votes. Common identities and expected counts must match. Partial feedback, global emptiness, stale/wrong identities and nonzero zero-variance input reject the entire update; no candidate is dropped and no fallback scale is chosen. A dead process/backend still requires the existing process-group timeout; this is not a process recovery service.

The common receipt binds the complete definition, common dependency identity, global count/moments and every rank’s rewards, validity, raw/normalized advantages and local identity hashes. It is identical across ranks. Local receipts retain the actual rollout and feedback identities. Reconstructing the same rollout/topology reproduces the receipt without consuming RNG. Native checkpoint/persistence wiring is owned by the Lead and is outside this module commit.

For an all-zero rollout `all_zero=true`, `std=0` and every output remains exactly zero. `gain=1e10` is the algebraic reciprocal of epsilon, not an observed policy amplification; consumers must interpret it together with `all_zero`. The original feedback statistics reported such an inactive effective gain as undefined. Do not combine these inactive receipt values with empirical active-signal scale distributions.

Actual validation: **29 tests passed**, no failures/skips, in **3.60 seconds**. The full output and exact command are retained. One two-process CPU/Gloo job exercised 4 successful uneven/24-scene-tail/empty-local-rank partitions and 10 one-rank faults. Both ranks rejected partial feedback, nonfinite rewards, wrong dtype/gradient state, expected population or common identity disagreement, malformed local identity/device, disabled collectives and actual count mismatch. Each child used one CPU thread, a 20-second group timeout and an outer 120-second shell bound.

Other tests compare correction-1 reference arithmetic, the FP32 global-recentering counterexample, all-zero BC preservation, Python/NumPy/Torch RNG preservation, full/microbatch and rank-averaged gradients, scalar gradient direction, valid-zero population inclusion, autocast behavior, and deterministic identity reconstruction. Mathematical gradient tolerances explicitly account for the prescribed FP32 output cast. These are synthetic behavior tests, not real model, official-scoring, GPU, native-checkpoint or scientific evidence.

No GPU, model/checkpoint, private scene, raw feedback payload or official simulator was used. No optimizer update or shared trainer/config edit was made. The independent review and Lead’s integrated real SMOKE/PROFILE remain required. This module does not self-approve training. Across optimizer updates the scale changes policy-versus-BC weights and EP/safety balance; no lossless or safety-benefit claim is made.
