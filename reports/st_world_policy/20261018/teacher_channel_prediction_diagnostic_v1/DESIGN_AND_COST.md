# Same-request channel alignment diagnostic

Question: at the same real5000-update/159992-exposure endpoint, does the256-channel student have lower error than the384-channel student on the **same first256 PCA coordinates**? Does the384 tail128 carry large absolute/relative residual error? A lower common error would support easier local alignment on these eight trained scenes; it would not establish faster convergence, causal gradient interference, better planning or population-wide superiority. Tail error alone does not prove those dimensions are harmful. No gradient-conflict measurement is included.

Existing design and mathematical implementation are reused: `teacher_channel_control_v1/channel_errors.py`; original fdf25f99 `load_world_checkpoint(strip=False)`, `STObservationDataset`, `TeacherCacheReader`, `TeacherPCA.transform`, `sample_requests`, `gather_current`, `SpaceTimeStudent.encode_inputs` and `SparseFeatureReadout`. The wrapper does not call `SpaceTimeStudent.forward`, planner/action/FM, backward or any optimizer. Teacher features are read from the already complete native384 train cache; no teacher network, new provider/index or cache builder is instantiated.

Fixed inputs: eight hash-selected rows from the existing score-free smoke_train64_pinned_v2 TRAIN manifest, seed20261018. Membership is rechecked against the actual shared full train manifest at execution. This is a bounded local diagnostic, not a representative whole-training-set estimate. No dev/navtest score is read. Same three views, teacher384×288/native18×24, W48/view,96positions/view. Patch seed4242 generates all8scene requests **once** with the original sampler, then the identical slices are reused for both models. Current target identity includes matching scene/log/timestamp and three image paths/content hashes.

PCA: original1024 channels are standardized by the same frozen train-only mean/std, centered, then projected by one unwhitened basis. Original256 and384 transforms are both executed on the same real maps. Their entire256-prefix must be bitwise equal; any difference writes TARGET_PREFIX_CHECK and fails without loosening tolerance. Both model predictions are compared to the common384-derived target and the same valid request mask. The256 arm has no tail prediction; it is reported NOT_PREDICTED, never fabricated as zero error. Per-component MSE, target mean/variance/energy and relative SSE are retained, as are common256 and extra128 summaries, exact IDs/mask and numeric hashes. No teacher/prediction tensor files are written.

Both models are evaluated in canonical **eval FP32 master execution, TF32 off**, with sparse_readout retained. This differs from original BF16 execution training and is not called training loss. Shared deterministic settings and forward RNG identity are recorded. Each endpoint is loaded by the existing strict loader exactly once, sequentially; no prior `checkpoint_identity` call or `export_world` wrapper adds a redundant pass. After each arm, model deletion, GC and weakref confirmation precede the next load. Source/state contracts, strict state load and native checkpoint checks remain intact. New scoring/teacher/model structures are absent.

Read budget basis, from small existing COMPLETE receipts only:

-256 endpoint:37,365,116,450bytes;384:37,366,035,746bytes, each nine native files/world4.
- Existing loader performs two full native checksum passes per endpoint:149,462,304,392bytes total before reconstruction costs.
- Three full-inventory equivalents total224,193,456,588bytes (208.80GiB) is a conservative planning allowance, **not measured I/O or a lower bound**. Installed DeepSpeed reconstruction uses mmap for optimizer shards and discards moments; rchar excludes mmap page faults. Reading optimizer shards is necessary for the true learned FP32 masters but creates no optimizer.
- Original reader parses145,979,873byte identity +170,157,016byte requests once; checksum passes, PCA-scope validations and the original train/current index add one-time reads. This is not a per-step repeated provider rebuild. Raw current shards for at most24images are read and strictly checked. Full population/cache identity checks are retained.
- Proposed one-shot envelope: one A80080GiB, two CPU threads,96GiB RSS,320GiB logical/full-inventory allowance,1800seconds,16MiB summary output; **not issued or measured**. Lead must attach the existing resource monitor and decide actual placement. This script only enforces its fixed8scene/2model/no-retry recipe and15MiB child-summary budget (plus1MiB separately reserved external controls); it does not claim hard external RSS/IO/wall limits. No checkpoint is saved and no old checkpoint reservation is released.

These tests exercise real small native request/readout/PCA functions with explicit fixtures, not real trained weights. Actual GPU/real-image acceptance remains NOT_RUN and must be reported separately. No results currently answer which arm aligns better.
