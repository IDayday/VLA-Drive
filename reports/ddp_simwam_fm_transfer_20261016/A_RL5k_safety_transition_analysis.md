# A组RL5k：新增TTC失败与纵向行为的配对分析

这次只读取既有5k权重及其自身20k SFT的完整评价记录，没有新推理、评分或参数更新。完整DEV为1,696场景/16logs，固定TRAIN诊断为512场景；两种网格仍分别使用seed2101的单候选。原始均分及安全转移见[5k主报告](interim_A_RL_update005000.md)。

新证据显示：**DEV新增TTC失败普遍伴随更大的前进量、更高的失败时刻速度和更不平滑的请求点；这些失败轨迹按源10:5:2奖励也全部低于自身SFT。** 这支持继续检查进度更新如何影响原安全行为，但不构成某个loss或时间网格的因果证明。

## 新增TTC失败的实际行为

下表只包含“同一网格下，自己的SFT通过TTC、RL5k未通过TTC”的场景，按场景等权。它是根据结果定义的诊断子集，不能当作总体无偏样本。

| DEV诊断项 | 原生均匀10步ODE | shift5 10步ODE |
|---|---:|---:|
| 新增TTC失败场景 | 28 | 8 |
| 来自多少完整log | 4 | 3 |
| 各log所含场景数（降序） | 12、8、4、4 | 5、2、1 |
| 首次官方TTC违规时间，中位数 | 3.9秒 | 3.95秒 |
| 首次违规发生于3.6–4.0秒 | 27/28 | 7/8 |
| 在首次违规时，比SFT前进更多 | 28/28 | 8/8 |
| 同一时刻的前进位移差，均值 | +0.8172米 | +0.5736米 |
| 该时刻之前0.1秒的平均段速度，SFT→RL | 0.9347→1.5526米/秒 | 1.4797→1.9342米/秒 |
| 同一时刻的平均段速度增加 | 28/28 | 8/8 |
| 整段模拟终点的前进位移差，均值 | +0.9444米 | +0.6315米 |
| 请求轨迹离散jerk分量RMS，SFT→RL | 0.4623→3.0315米/秒³ | 0.9158→2.2971米/秒³ |
| 这些场景中RL的NC未完全通过数 | 0 | 0 |

位移投影到两条轨迹共同的初始车头方向，速度来自同一物理时刻之前0.1秒的模拟位置差；不是在两条轨迹各自的不同位置或不同时间做比较。所有配对初始模拟状态完全一致，评分cache与协议身份也一致。

首次违规时间直接读取锁定评分器的 `time_to_ttc_infraction` 输出，即首次官方TTC判据失败的模拟时间。它不是预测碰撞倒计时，也不是Flow生成步骤。这里不能说“第4秒发生了28次碰撞”，更不能将这些时间映射到第7/8/9个Flow步骤。

请求jerk是原8点XY请求序列的有限差分分量RMS。它描述请求形状，不是官方Comfort判据，也不是实际车辆的瞬时jerk。请求与模拟轨迹分别保留，分析没有用模拟轨迹替换模型输出。

## 不能仅用训练reward与metric不一致解释

将同一份已评分分项分别按10:5:2和canonical5:5:2重组：

| DEV人口 | 原生canonical变化 | 原生source读出变化 | shift5 canonical变化 | shift5 source读出变化 |
|---|---:|---:|---:|---:|
| 全部1,696场景均值，百分点 | +0.6123 | +1.1453 | +0.9238 | +1.2314 |
| 新增TTC失败子集均值，百分点 | −39.5285 | −26.3932 | −39.8995 | −26.9170 |
| source改善但canonical退化的场景数 | 0 | 同左 | 0 | 同左 |

最后一行使用原始score差的`1e-12`数值容差；按两侧至少0.005的实用幅度统计也为0。原生28个和shift5的8个新增TTC失败，其source读出都严格下降。这不是训练时的G8随机策略均分，而是对两条已部署ODE轨迹做的同反馈双读出。

因此，本批结果不支持“这些具体失败轨迹在source奖励下反而更好”这一直接解释。但10:5:2对TTC损失的相对权重仍低于canonical，可能改变跨候选、跨场景的梯度权衡；这个分析没有排除奖励权重的影响。训练时的组内相对排序、随机状态覆盖和部署轨迹分布仍与这项配对比较不同。

## 收益和退化集中在哪里

原生DEV的正向总收益G+为24.462237、负向总退化G−为14.078394，均为原始0–1 score的场景求和。原SFT-safe人口中新违规的31个场景贡献13.964656，约占全部G−的 **99.19%**；其中新增TTC的28个场景贡献11.067978，占G−的 **78.62%**。shift5相应为10个新联合违规贡献G−的 **98.00%**，新增TTC贡献 **61.66%**。

与此同时，原生有458个场景在SFT和RL均通过NC/DAC/TTC、且PDMS至少提升0.005原始score（0.5个百分点）；它们分布在15个log，平均PDMS提升2.8476个百分点，模拟终点前进位移平均增加0.6912米。shift5对应412个场景、15个log、平均提升2.3298个百分点、前进增加0.5422米。

前进增加同时出现在安全获益场景和新增失败场景。当前证据更具体地指向“如何保留有益的纵向改善、并避免把相似变化迁移到需要更保守的场景”，而不是要求所有场景一律多前进或少前进。28个原生失败来自4个log，不能将28个scene当28个独立训练复现。

## 两种网格与TRAIN诊断

相对于各自匹配网格的SFT，新增TTC场景有5个同时出现在两种网格，23个仅出现在原生的新增集合，3个仅出现在shift5的新增集合。对RL当前输出本身，TTC失败有8个两网格共有、21个仅原生、5个仅shift5。

这表明同一权重下的失败集合对生成时间网格敏感，但不证明采样迁移是唯一瓶颈。两种网格的SFT起点也不同；完整DEV原生减shift5的PDMS区间仍跨零，不能做逐场景best-of-two或改报较高网格来宣称解决问题。

固定TRAIN诊断中，原生新增TTC为20场景/19logs，shift5为11场景/11logs。首次失败时速度分别在20/20、11/11场景增加，平均差为+0.4340、+0.2862米/秒；前进位移分别在19/20、11/11场景增加。原生这20个场景中有4个NC未完全通过，说明该诊断人口的失败类型更复杂。两种网格都没有source读出提高而canonical下降的场景。该集合包含定向困难样本，不用它替代完整DEV。

分析器重新核验全部配对scene payload hash、完整分母、自己SFT的身份及协议。四个人口/网格组合的均分、TTC新增/恢复、原安全人口新增违规、G+和G−均与已发布分析一致，原记录未修改。
